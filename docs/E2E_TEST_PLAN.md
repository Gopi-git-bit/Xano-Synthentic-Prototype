## Runbook (local isolated fixtures)

Start from the repository branch containing `frontend/`, not Xano-only `main`:

```sh
cd frontend
npm ci
npm run typecheck
npm run lint
npm run build
npm run test:server
npx playwright test
node scripts/scan-browser.mjs
```

Install an appropriate Edge browser for the Playwright `msedge` channel where the test host lacks it. Ensure development API servers are not already occupying ports 3001, 5174 or 4173; Playwright starts its own. Tests should use mocks and fixtures, not provider secrets or real tenant data. Never paste token contents into CI logs.

## Coverage matrix

| Area | Existing browser coverage | Release acceptance |
| --- | --- | --- |
| Customer | Draft booking validation; restored inputs; search/empty states | No operational booking/payment success from a local draft |
| Vehicle owner/driver | Salaried vs fleet owner scope; offer/online state; POD evidence drafts | No unauthorized financial view, assignment, upload or verification |
| Admin | Scoped review/CRM unavailable; no live provider fetch | No forged approval or unauthorized CRM mutation |
| Role isolation | Prevent self-assigned roles; exclude fixture bundles in production | No role selector or demo JavaScript in release bundle |
| Accessibility/UI | Role palettes, responsive widths, screenshots, keyboard, targeted axe | No major mobile overflow, inaccessible dialog or contrast regression |
| Xano integration | Mock booking contract, stale record clearance on denial, disabled auth entry | Gate remains fail-closed until published positive/negative contract tests |
| API failures | Server adapter tests for denied/incomplete/malformed/timeout responses | Fail closed; no false success, leaked token, tenant record or unsafe retry |

## Before enabling live integration

Use an authorized, isolated test environment and an approved set of synthetic identities with distinct tenant and role memberships. Verify: valid login/me, denied/inactive identity, authorized customer booking read, cross-tenant denial, invalid/missing payload rejection, sign-out/session expiry, explicit human approval on finance/refunds, audit logging without credentials, and deterministic status handling. Separately verify POD submit-versus-verify and payment hold/settlement before opening any mutation path.

**Do not** make live Xano calls, change release flags, publish Xano schemas, charge real payment instruments or test real customer accounts as part of this documentation-only PR.

## CI and reporting

Future CI should run typecheck, lint, build, server mocks, Playwright and browser secret scan on the **frontend branch and its PRs**, with a pinned Node/toolchain and installed browser. Test only preview/fixture flows until backend approvals. Save test results, screenshots and the exact commit SHA; redact secrets. Do not make merge-to-default-branch equivalent to production release.
