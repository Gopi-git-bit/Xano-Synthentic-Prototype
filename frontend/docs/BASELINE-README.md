# Zippy frontend — historical baseline (superseded)

Current instructions and integration status are in `../README.md` and `DELIVERY.md`. This file preserves the first delivery record; its role URLs and production-gate details are historical.

Role-themed logistics workspace reconstructed from the accessible, published Zippy prototypes. The original repository had no frontend or logistics PRD. The reference JavaScript was plain DOM templates, with custom CSS; no React or Tailwind build was available. Shared layout, truck illustration, map treatment, navigation, fixture records and booking stages informed the component reconstruction.

## Local preview

```powershell

```

Open these **development-only** workspaces:

- Customer: http://127.0.0.1:5173/?preview=customer
- Driver: http://127.0.0.1:5173/?preview=driver
- Vehicle owner: http://127.0.0.1:5173/?preview=provider
- Admin: http://127.0.0.1:5173/?preview=admin

The role selector is a local fixture preview, not authentication. Drafts live in memory; booking fields survive step changes and navigation, while some independent forms reset when leaving their view. Reload resets all fixtures. No remote business API is called.

## Production build

```powershell
npm run typecheck
npm run lint
npm run build
npm run preview
```

Production serves an **access-unavailable screen**. Vite eliminates the development application and all fixtures/role-preview code from production JavaScript. Supplying `?preview=admin`, a hash, or local storage cannot unlock it. This is deliberate: the repository's `admin/member` authentication schema does not define customer/provider/driver permissions or logistics APIs.

This frontend does **not** implement or claim backend authorization. There are no connected protected operations. Before enabling operational pages, use the approved authentication contract and require the backend to authorize every operation and record; frontend navigation is never an access control. No Xano file was changed.

## Styling

- React 19.3.1, Vite 8.3.5, TypeScript 6.0.3, Tailwind 4.3.3; exact resolution in `package-lock.json`.
- Tailwind is compiled with `@tailwindcss/vite` and `@import "tailwindcss"`; no runtime CDN.
- Semantic tokens: canvas, surface, ink, muted, line, brand, brand-hover, brand-soft, nav, success, warning and danger.
- Customer: ivory `#FBF6EE`, green navigation `#27352D`, orange `#CD5128`.
- Contrast shades: customer small labels use `#A53D1B`; white-label action fills use `#BA4822`, retaining the requested orange accent/border. Blue muted text is `#516379` for readable text on pale-blue surfaces.
- Driver/provider: pale blue `#EDF4FC`, navy `#152E4F`, blue `#2563B8`.
- Admin: soft violet `#F3EFFA`, deep purple `#302142`, violet `#7950AE`.
- Status colors do not change between roles. Fonts are bundled locally. Controls use 180–200 ms transitions, visible focus, reduced-motion support and approximately 44 px targets.
- English/Tamil navigation is a layout preview, not a complete Tamil translation. Tamil text entry is supported; the remaining content needs localization.

## Verification

```powershell
npm run build
npm test
```

The tests start isolated development and production-preview servers on 5173/4173, and use the locally installed Microsoft Edge. On another machine, install Edge or change `channel` in `playwright.config.ts` to an available browser.

Screenshots are regenerated by the tests. Automated accessibility checks cover the customer, driver and admin dashboards and key workflows; they are not a claim of complete accessibility certification. Responsive checks cover 320, 390, 768, 1024 and 1440 px, with every navigation destination checked at 320 px.

To attempt read-only reference captures again:

```powershell
node scripts/capture-references.mjs
```

Owner access / hosting protection may prevent captures. The script records that outcome and does not attempt to bypass it.
